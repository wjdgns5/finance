# Phase 5 — 4탭 대시보드 검증

검증일: 2026-11-17. 프론트엔드·백엔드 버전: 0.5.0.

**Phase 5 구현·자동 테스트·HTTP 통합·실제 브라우저 검증 완료.** Phase 4의 사용자 공시 화면 대조는 별도로 미확인 상태를 유지합니다. Phase 6은 사용자 확인 후 진행합니다.

## 구현 완료

- 기업개요·재무정보·현금흐름·투자지표 4개 탭, KPI 4종, 차트/표 및 카드/표 전환.
- 최근 연간 매출액 막대와 영업·순이익률 선, 오른쪽 % 보조축. 자산·부채·자본 및 3종 현금흐름 차트.
- 연결/별도 기준 선택. 차트는 서로 다른 기준과 누락 연도를 연결하지 않음.
- 공시 기간·접수번호·출처·재무 연도·주가 기준일·수집 시각·N/A 사유. ROE·ROA 기말 기준.
- 마우스·클릭·키보드용 정보 툴팁, ARIA 탭, 반응형 레이아웃.
- 기존 계산 엔진을 재사용하는 `GET /metrics/profitability?years=5`. 새 DB 마이그레이션 없음.

## 설계 설명·학습

프론트엔드는 계정 금액과 백엔드 계산값을 표시합니다. 연도별 이익률도 서버가 계산해야 지표 공식과 N/A 기준이 두 곳으로 나뉘지 않습니다. 금액은 원본 문자열을 유지하고 그래프 좌표만 Number로 바꿉니다. 기준·공시가 다른 병렬 응답은 함께 표시하지 않습니다.

직접 해볼 것: 990004에서 차트 기준을 바꾸고 두 연도의 값이 한 선으로 이어지면 왜 비교가 부정확한지 설명해 보세요.

면접 질문과 답변 요점:

1. 이익률 이력 API를 추가한 이유는? — 같은 BigDecimal 엔진과 N/A 정책을 모든 연도에 적용하기 위해서입니다.
2. 큰 금액을 바로 Number로 바꾸지 않는 이유는? — 표·툴팁에서 원본 정밀도를 보존하기 위해서입니다.
3. 차트 지연 로드의 효과는? — 첫 검색·요약 화면에서 차트 라이브러리 다운로드를 미루고 초기 번들을 줄입니다.
